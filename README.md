# 学マス回忆工具

Windows x64 便携工具：只读读取本机《学园偶像大师》游戏中已加载的回忆，转成 Stage 编成，在本地做竞技场全库搜索与赛季三场比较。解压后双击 `GKMemoryTool.exe`，不需要安装 Python、Node 或配置终端。

- 下载（正式最新版）：<https://github.com/BriAutumn/gakumas-screenshot-tool/releases/latest>
- 使用说明：<https://github.com/BriAutumn/gakumas-screenshot-tool/releases/latest/download/user-guide.html>

> 公开仓库地址保持 `BriAutumn/gakumas-screenshot-tool`，用于兼容更新器。旧截图识别方案已停止维护。

## 快速开始

1. 在启动器里用“选择游戏”指定 `gakumas.exe`，或用“自动查找”。游戏关闭时点击“安装 / 更新插件”。
2. 通过 DMM 启动游戏并进入主页面。插件只读取本机已加载的回忆，不修改游戏数据；每次游戏启动后导出一次。
3. 回到启动器点“打开模拟网页”，在网页里点“读取最新回忆”。工具自动找到导出文件，按原生映射转换成 Stage 库，并在下拉菜单里选中新库。
4. 选择赛季、舞台与支援加成，点“搜索当前舞台”，或“启动本赛季三场轮转”。历史结果存在本机，暂停后可继续。

旧版 `memories.json` 可在启动器的“导入旧导出文件”里手动选择导入。新增回忆后重新启动游戏，再点“读取最新回忆”。

## 1.0.13 启动修复

修复部分电脑安装插件后没有新导出，以及自动启动过早引发 GC 致命错误的问题。后台启动先等待本游戏的晚启动模块信号，再注册线程和读取回忆；保留原代理触发作为备用，避免重复导出。等待与导出合计最多三分钟；过期的读取状态会明确提示未更新。

升级程序后，请在游戏关闭时再点击一次“安装 / 更新插件”，然后启动游戏进入主界面。保留汉化插件共存逻辑；未保证所有汉化版本兼容。使用过 1.0.12 测试包的用户应停用该包并升级。

## 插件与游戏导出

- 插件默认使用 `version.dll` 与本工具配置。检测到其他插件的 `version.dll` 时，自动改用自带的 `winhttp.dll` 入口并保留原 DLL；两处入口都被占用时拒绝覆盖。游戏运行时禁止安装、更新或卸载。
- 每份导出都带状态与快照校验；校验不一致时“读取最新回忆”会提示，旧导出可用“导入旧导出文件”手动读取。
- 卸载插件只移除本工具拥有的 DLL 与配置文件，改动过或其他工具的文件会保留。
- 活动与联赛暂不支持，只处理普通竞技场舞台。

## Stage 与 Produce

只有含舞台卡组 / 舞台道具的记忆会转换成可搜索的 Stage 编成。Produce / 无舞台数据的记录会在导入结果里单独计数并跳过，`读取最新回忆` 会同时显示 Stage 可用数量、跳过数量与转换失败数量。

原生映射覆盖整个固定目录，不限于开发者自己拥有的回忆；来源与版本记录在 `assets/native/mapping.json` 的 provenance 中。

## 全库搜索与赛季比较

- 网页会遍历当前库中同角色、同计划的全部主副组合；主、副互换视为不同组合。
- 单个舞台：先分阶段做候选初筛，再对入选候选做独立复测，筛选条件会随数据自适应，不写死固定次数。
- 赛季比较：在同一赛季的三个普通竞技场舞台之间依次轮转，逐个搜索后统一查看。
- 搜索是采样筛选，不保证理论最高分；“接近第一”只表示当前采样下差距在误差范围内。

## 回忆封面

回忆封面优先显示游戏本机缓存的原始玩家照片：仅当导出快照校验一致、且能在固定的 `LocalLow` 照片缓存目录找到对应文件时才显示，全程只读，不依赖视觉匹配。缓存缺失、导出为旧版本或文件损坏时会显示中文说明，不会用其他图片代替；未缓存的照片需先在游戏中打开该回忆。

使用内置封面时，按原生 `AssetId` 精确读取工具附带、记录过资源哈希的对应封面。玩家照片不会放入分发包。

## 数据目录

数据默认保存到 `%LOCALAPPDATA%\GKMemoryTool`，不在程序目录。移动程序或更新不会删除数据。需要换目录时可用 `--user-home "D:\回忆数据"` 启动工具，并重新安装插件来同步导出位置。

本机回忆与账号数据只在本机处理，不上传。

## 更新：两条独立渠道

**赛季更新时请同步上游。** 安装或回退模拟数据后，重启工具并再次读取最新回忆。

1. 程序 / 插件更新（启动器“程序更新”区）：只接受本工具专用发布渠道，即 GitHub `memory-tool-*` 标签的 Releases。完整更新包包含程序、插件、引擎、卡片目录和原生映射，校验后安装到独立版本目录。可“检查程序更新 / 安装本地更新包 / 回退上一版本”，回退保留用户数据。
2. 模拟数据同步（启动器“模拟数据”区）：直接从 GKTools 官方仓库和公开原生 ID 数据源获取引擎、卡片目录、原生映射与图标，走“同步上游数据 / 回退模拟数据”，常规更新无需重新打包 EXE。先检查上游，没有变化时显示已是最新；有新版本时只显示将要安装的数据版本（SHA）与变更摘要，确认后后台下载、校验并原子安装到独立版本目录。

安装或回退模拟数据前，工具会确认没有正在运行的搜索 / 模拟 / 赛季任务，并暂时禁止启动新任务；已经在跑的搜索会用它启动时固定的那份数据跑完。安装、回退完成后需要重启工具才生效；重启后再点“读取最新回忆”，会按新的原生映射重新生成本地快照。旧的结果与历史仍归属它们当初使用的数据版本。同一进程在生命周期内始终使用固定的数据版本。

## 兼容性与限制

- 插件自动共存已通过隔离加载和安装 / 卸载验证，尚未完成真实游戏内汉化与导出同时运行的联调，不保证兼容所有插件。

- 活动与联赛暂不支持。
- 官方上游若出现当前程序还不认识的全新机制，仍可能需要等本工具更新适配；这类未知内容不会被当作已兼容。
- 原生映射存在少量尚未完成效果独立核验的候选对应，能执行模拟不等于所有效果都已逐项证实；不支持的新 ID 会明确报错并保留原始导出。

## 关闭、卸载与回退

关闭启动器会取消运行中的搜索并保存进度。如果更新文件损坏，运行 `GKMemoryTool.exe --baseline` 可直接打开原版进行回退；不要只复制 EXE，保留整个解压目录。

## 开发

开发环境：Python 3.13。

```text
pip install -e .                      # 安装项目与依赖
python tools/prepare_node.py          # 准备固定的 Node 运行时（node.exe 不纳入 Git）
python packaging/entry.py             # 运行工具
python -m unittest discover -s tests  # 运行测试（不需要私有素材）
```

Windows 构建：

```text
pip install pyinstaller==6.20.0
python packaging/build_windows.py     # Windows x64，PyInstaller 6.20
```

原生插件二进制已随仓库附带（`assets/plugin/`，版本与 SHA-256 记录在 `assets/plugin/plugin.json`）。

更多细节见 [docs/development.md](docs/development.md) 与 [runtime/node/README.md](runtime/node/README.md)。
