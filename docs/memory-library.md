# PC 独立记忆库

这是游戏里的独立「メモリー」入口，与竞技场编成汇总页分开处理。
一份持有记忆保存 **4 个道具槽、6 个卡槽、自己的属性与所属偶像版本**；不包含场地、支援加成或主 / 副槽位。
后续组合器从记忆库选取主、副记忆，再生成原有的 Loadout。

## 使用窗口

0.5.14 起，列表的状态列直接显示“待解决：道具 1”等具体原因；选中记录后可在状态栏查看完整原因，编辑窗口顶部也显示同一信息。卡片全部“无自定义”不代表道具、属性和卡片身份都通过自动检查。已人工核对的状态优先，不会被旧的自动检查记录覆盖。

P 道具的普通版与强化版共用图案，因此单独核对右上角“+”的图形证据。清晰度不足或对齐误差较大时继续保留待解决，不会将候选当成已确认。旧采集原图可重新离线处理，不需要仅为更新识别规则重新采集。

双击 `launch-memory-library.cmd`，或在原来的 `launch.cmd` 窗口里点击“持有记忆库”。

1. “选择详情截图（多选）”：一次只选同一份记忆的上半页、下半页等详情截图。
2. 可选“选择列表定位图”：列表图中应选中这份记忆。
3. 点击“导入这一份记忆”。原图会复制到项目内，之后无需依赖剪贴板临时文件。
4. 中央绿色数字角标清晰缺席时，自动填无自定义；有角标的卡片读取详情。识别完整、证据及目录检查通过后显示“已自动识别”，无需逐张确认。
5. 仅有待解决项的记录需要补图、补规则或手动修正；选中记录可以查看具体字段。双击仍可查看或修改，人工修改保存时需确认。程序结果不覆盖人工修正。

`ready_only=True` / `memory-list --ready-only` 返回已自动识别和已人工核对的可用记录；旧 `reviewed_only` 筛选仅包含人工核对记录，保留原语义。

在第 4 步之前，可以选中记录，点击 **“读取选中记忆的卡片详情”**，多选同一份记忆的浮动详情截图。程序会自动识别卡名并绑定唯一卡槽；匹配成功的强化直接保存到草稿，不需要再手动填写该字段。当前支持「びしっとキメ顔+」，且同次处理会依据当前卡片 ID 为不允许自定义的卡派生空效果。其他卡仍保留未知。详情、支持范围及离线验证见 [card-detail.md](card-detail.md)。

本次三张样例已经作为一份**待核对**记忆入库，可直接查看。“试用新示例”重复点击也不会重复创建。
游戏点击和滚动采集已另设预览入口 `launch-capture.cmd`，见 [采集器说明](capture.md)；记忆库窗口自身只处理图片。组合遍历和模拟排名尚未实现。

## 多页处理

- 自动定位示例窗口上方的彩色画面，去除 Windows 标题栏和边缘，统一到 1080 宽。
- 固定页头里的标题、人物名、综合力及图像特征用于检查是否可以合并。**它们不是游戏唯一 ID**，同次导入仍需由用户明确选择同一份记忆。
- 上半页读取属性与道具；滚动区域按卡片边界定位，四列首行确定槽位，下一行补第五、六张。
- 不读被底部导航遮挡或只露出一部分的卡片。当前至少需要一张图能看到完整的四列首行；像本次下半页同时显示 6 张卡片最可靠。
- 相同槽位的重复观测合并并保存来源；不同槽位即使卡片相同也保留。冲突变为未知，不由后读的图片覆盖。
- 列表图只核对选中记忆的画面与综合力，保留为返回游戏查找的线索，不填补详情中缺失的属性。没有读取或遍历列表里的其他记忆。
- 模型低分时，用固定版本的卡片图标模板辅助识别；自动检查未通过时列入待解决项，不再将所有候选统一要求人工核对。
- 总览中中央绿色数字角标清晰缺席时，自定义自动为空字符串；有角标时仅据此确定需要详情，不猜具体效果。模糊、缺图或冲突保留 `null`。

当前支持本次 PC 竖版完整窗口布局及等比例缩放，尚未验证其他窗口比例、全屏布局、其他滚动状态或其他真实记忆。
页头不一致、选择到「プロデュース」页、列表 / 编成页混入详情图，均拒绝合并。
识别不齐可以先作为“缺少画面”记录入库；当前补充截图应重新选择完整的一组再导入，尚未实现自动关联到旧记录的增量补图。

## 存储

默认目录为 `data/memory-library/`，包含 `library.sqlite3` 和 `sources/` 原图。备份或迁移时复制整个目录。
保留原始识别报告、每个字段的截图来源、人工核对结果与版本；人工核对不会改写识别报告。

同一组详情原图按哈希识别重复导入，顺序不影响结果。后补列表定位图不会多生成一份记忆。
**不按角色名、综合力或属性相同就删除记录**，不同持有副本必须可以并存。
批量清单的 `capture_id` 是采集会话给某一份持有记忆的稳定标识；明确使用不同 ID 可以保留内容相同的独立副本。
重新截图、重新裁剪或增减详情页会形成新采集组，当前不能保证自动认出是同一份旧记忆；这种情况需核对后再整理，不做不可逆删除。

## 命令行

```powershell
# 两张详情 + 可选列表图，合并入默认记忆库
.venv\Scripts\python.exe run.py memory-import tests/fixtures/memory-library/detail-top.png tests/fixtures/memory-library/detail-bottom.png --context tests/fixtures/memory-library/list.png

# 只生成识别报告，不入库
.venv\Scripts\python.exe run.py memory-scan tests/fixtures/memory-library/detail-top.png tests/fixtures/memory-library/detail-bottom.png --output work/memory-scan.json

# 查看记录 / 只取已核对记录
.venv\Scripts\python.exe run.py memory-list
.venv\Scripts\python.exe run.py memory-list --reviewed-only

# 按显式分组清单批量导入，示例使用独立演示库
.venv\Scripts\python.exe run.py memory-batch examples/memory-batch.json --library work/batch-demo-library
```

批量清单中的图片路径相对清单文件解析。每份记忆占一个分组，不能把所有详情图放进同一个数组。
某组失败会返回错误，其他组继续；重跑相同清单可跳过已建立的相同采集记录，但仍会重新识别图片。

## PC 自动采集入口

已明确的流程是：

`记忆列表 → 选择缩略图 →「詳細を見る」→ 确认「ステージ」→ 截上半页 → 在下半部详情区域滚动 → 截卡片完整页 → 合并检查 → 返回列表 → 下一份`

自动化需要根据画面确认状态、等待稳定、保留列表定位与重试记录。列表排序或新增记忆后不能沿用旧坐标。
列表里能看到「プロデュース専用」条目；后续应识别并跳过不能用于目标场景的条目，不能把 496 的总持有数直接当作可用记忆数。
该流程现由独立采集器实现为预览版，保存原图和进度；尚待实际游戏试采验收，不依赖所有强化规则已经完成。参见 [capture.md](capture.md)。
