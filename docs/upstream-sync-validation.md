## CSV-only 上游适配（本地物化 JSON，2026-11-02）

上游不再提交 `packages/gakumas-data/json/*.json`，权威数据表改为 `packages/gakumas-data/csv/*.csv`。数据同步器现在在暂存目录内本地生成 JSON 兄弟文件（`packages/gakumas-data/json/<table>.json`），规则如下：

- 覆盖 `csv/` 下的**全部**表（`idols`、`p_drinks`、`p_idols`、`p_items`、`skill_cards`、`stages`、`customizations`），而不只是 4 个目录表：引擎运行时导入 `p_idols` / `idols` / `p_drinks`，原生映射构建也需要 `p_idols` / `idols`。
- 若同名上游 JSON 已存在则直接沿用，绝不重写；只有缺失的表才转换。
- 转换语义与当前上游 `packages/gakumas-data/utils/csv.js` 一致：`TRUE` / `FALSE` → 布尔值；纯数字 → 整数；其余保持原字符串（如 `0.5`、`-1`、空字符串）。支持 UTF-8 BOM、引号内的逗号与换行。
- 非法输入一律报错，不静默丢弃或跳行：非法 UTF-8、空/重复/带多余空白的表头、字段多于或少于表头、无法解析的数值、缺失或重复或非正整数的 `id`。
- 输出为紧凑 JSON（`separators=(",", ":")`、`ensure_ascii=False`），表按名称排序、键按表头顺序，逐字节确定；引号内 CRLF 原样保留，纯数字限定为 ASCII 0–9。
- 生成发生在写 `runtime/node/manifest.json` 之前，因此生成的 JSON 同时被运行时清单与 `release.json` 文件清单覆盖（重新安装 / 回滚时重新哈希）；`p_idols` 缺失直接失败，不会把偶像数量记为 0。
- `assets/recognition` 仍只携带 4 个目录表；由 CSV 生成时其 `manifest.json` 的 `upstream_path` 记录为对应的 `packages/gakumas-data/csv/<table>.csv`。

已读取当前上游 `utils/csv.js` 核对类型转换和换行语义；922 张技能卡、509 个道具、192 个场地和111组自定义通过目录校验。525 个上游回归案例全部通过，worker 与 reference 同种子3次模拟分数完全一致。同步相关79项回归通过，2项按平台条件跳过。
