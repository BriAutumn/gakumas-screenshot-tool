开始使用

  1. 完整解压发行 ZIP，再双击包内的 GKTool 程序。预览包入口名为 GKTool-preview.exe，请勿只复制 exe。
  2. 正式打包版本自带运行环境，无需另装 Python 或 Node；日常使用不需要 GPT、API 密钥或联网。
  3. 工作台按四步排列。已有原图可以直接从第 02 步开始，已有可用库可以直接进入第 04 步。

工作台的四个入口对应上方流程，下方可打开数据目录、日志目录，或运行诊断。源码用户使用 launch-desktop.cmd，首次环境准备沿用 setup.cmd。

工具窗口各自独立运行。关闭工作台不会中止已启动的采集、识别或模拟；请从对应窗口停止任务。

01 · 采集回忆原图

  1. 打开 PC 游戏，进入独立的 memory 回忆列表。保持筛选、排序和窗口大小不变。
  2. 工作台点「打开采集器」，在「原图采集」页选择游戏窗口；找不到时点「刷新游戏窗口」。
  3. 首次点「新建采集会话」，然后点「一份试采」。在工作台「数据目录」的 data/captures 中找到这次会话，查看 raw 内的原图，确认画面正常。
  4. 设置「本批最多」数量，点「开始 / 续采」。开始后采集器会操作鼠标，请保持游戏前台，不要同时操作游戏。
  5. 需要中断时按 F8 暂停或 F9 停止。等待当前步骤结束和日志更新后，再关闭窗口。

下一次继续采集

点「打开已有会话」，选择该会话的 session.json，让游戏回到同一列表后点「开始 / 续采」。默认在当前列表附近寻找断点，不必每次回到顶部。

「从顶部重新核对」和「采集所有卡片详情」通常保持关闭。若要补更早的待补项，可同时勾选「重试当前位置之后的待补记忆」和「从顶部重新核对」。首次标定只在画面定位确实不适配时使用；已有会话保留创建时的标定。

若提示权限不一致，而游戏正以管理员身份运行，请停止并关闭当前采集器，再以管理员身份启动工具。自动切到游戏失败时，可以勾选「手动切换到游戏」，在点击开始后的 3 秒内自行切换。

02 · 关掉游戏，离线识别

  1. 工作台点「处理已有会话」，直接进入「离线识别」页。
  2. 点「打开已有会话」，选择之前采集目录里的 session.json。
  3. 点「离线识别本会话」，等待日志更新。活动条表示正在工作，不代表准确的完成百分比。
  4. 处理结束后，只要有成功入库的记忆，程序会打开本次结果库。也可点「查看本会话最近结果」。
每次识别会新建处理批次，保留原图、旧结果和以前的核对记录。取消后请查看本次日志；重新识别会生成新的批次，不要当作从上一条原样续跑。

「采完」和「识别完整」是两件事。请看结果库中的可用、待解决和缺少画面状态，不要只依据处理结束或没有报错来判断数据齐全。

03 · 查看结果，只核对必要项

先确认窗口上方的「当前库」路径。手动导入库和每次离线识别的结果库分开保存；如果工作台打开的是空库，可点「查看最近采集结果」，也可回到采集器从指定会话打开结果。

想做什么操作
快速查找输入人物名、标题或内部记忆 ID，配合「全部 / 待解决 / 可用于模拟」筛选。
排查待解决项选择记录，查看状态说明；点「查看归档原图」对照证据，双击记录或点「核对选中记忆」修改。
补充卡片详情选中记忆后点「读取选中记忆的卡片详情」，导入属于该记忆的详情截图。
手动导入一份选择同一份记忆的多张ステージ详情截图，可补列表定位图，再点「导入这一份记忆」。不同记忆分次导入。

「已自动识别」与「已人工核对」是现有库状态；「可用于模拟」表示字段通过当前可用性检查，不是自动识别准确率。有待解决项或缺少画面时，需要补图、补规则或核对。

未知自定义不能直接当作没有。少于六张卡可以合法，但只有确认不存在的槽位才填空；名字末尾的「+」表示普通强化，不等于自定义强化。确认修改无误后，再勾选核对确认并保存。

04 · 在本地网页运行模拟

工作台点「打开模拟网页」。浏览器会打开本机地址，同时出现「本地模拟服务」窗口。网页在本机运行，不需要上传记忆库。

选择场地核对支援加成
选择主副记忆明确使用哪份库
设置次数并模拟等真实结果完成
比较与导出查看均分和波动
  1. 先选择目标场地并填写支援加成百分比。
  2. 点「从记忆库选择」，明确选中刚才的结果库，再选主、副记忆。两份必须为兼容的同角色、同计划记忆，不能把同一持有副本同时用作主副。
  3. 检查属性、道具、卡片及自定义强化，设置运行次数，点「模拟」。也可以导入已有 GKTools 链接或完整编成 JSON。
  4. 完成后查看平均分、中位数和分数分布。首次试用可少跑一些确认流程，再增加次数比较接近的编成。
  5. 想比较多个编成时，为当前编成命名并「加入候选」，切换下一套后重复，最后点「比较所有候选」。候选应在同一场地比较。

全库排行榜（可选）

网页下方「全库排行榜」使用当前场地、支援加成和种子。选择搜索库，先「统计组合」，再「开始全量搜索」。查看 100 次初筛与 2000 次复测的对应榜单；尚未完成的榜单只是暂定结果。复测名额和筛选策略以所用版本页面为准。

可以在总榜、角色榜之间切换，选择 2–4 组对比，或载入编辑、查看分布、导出 CSV。搜索时点「停止并保留结果」，随后从已保存搜索中继续；普通模拟用「停止模拟」。更换引擎版本后，旧搜索可能不能续跑。

榜单按模拟样本比较，并不证明游戏中的绝对最优。均分接近时也要看波动与次数；本功能不替你完成跨三场的整队分配。

保存与退出

历史保存在当前浏览器本地；普通历史最近 20 条，点击 ☆ 可保留。重要编成导出 JSON，重要成绩导出分数或榜单 CSV。不同浏览器/端口的历史不共享，清理浏览器数据会丢失历史。

关闭浏览器不会停止后台服务。用完后，在「本地模拟服务」窗口点「停止服务并关闭」，等待正在运行的任务退出。如果刚识别的新库没有出现在网页中，先停止服务，再从工作台重新打开网页以刷新库列表。

数据保存、更新与常见问题

发行版默认把数据保存在 %LOCALAPPDATA%/GKTool，以工作台「数据目录」显示的位置为准。源码版默认在项目目录；设置过 GKTOOL_USER_HOME 时使用该指定目录。

备份时先停止相关任务，再复制整个数据目录。更新程序时，将新包完整解压到新的程序目录，不删除数据目录。只复制 library.sqlite3 不包含全部原图证据。

遇到的问题先这样处理
找不到游戏窗口确认 PC 游戏已打开，再刷新；仅做离线识别不需要游戏窗口。
采集暂停或定位失败看日志，回到原 memory 列表，保持原筛选和窗口大小，再续采。不要清空已有会话。
记忆库为空 / 数量不对先核对「当前库」路径和筛选条件，再从目标会话打开本次结果。
网页显示没有可用记忆检查库选择、可用状态以及场地计划；新库生成后可重启本地模拟服务。
本地服务端口被占用先关闭已有 GKTool 模拟服务窗口，再重新启动；不要关闭不认识的进程。
工具不能启动或运行失败工作台点「运行诊断」，查看 logs/diagnostics.json；启动异常看 desktop.log 和 startup-error.txt。包损坏时完整重新解压。

反馈问题时附上执行到哪一步、具体错误文字和对应日志即可。需要分享截图时，先确认其中没有不想公开的个人资料。
