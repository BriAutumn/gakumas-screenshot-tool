`axes` 必须涵盖卡片目录列出的每一个自定义项目。`numeric` 项指定目录字段、基础值和增减方向；`text` 项明确列出各等级出现的文字，`null` 表示未支持，不能解释为空效果。完整目录指纹变化、无法完整解析的数值表达式、缺少项目或多个匹配状态都不会自动填写。

正文不显示普通消耗的卡可要求 `corner_cost_required`：从同次展开前原图读取右下角负消耗，并核对唯一卡片及卡槽，不能仅靠正文猜是否降低消耗。目前限清楚的一位负消耗；重复同名卡、像素不足和读数不一致保留待解决。孤立换行字形只从实际像素识别，不能因模板预期存在就补入。

0.5.28 新增 8 张卡的完整效果规则：国民的アイドル+、届いて！+、きらきら紙吹雪+、立ち位置チェック+、ティーパーティ+、テレビ出演+、一心不乱+、ゆめみごこち+。目前共 13 张卡有规则，尚不表示全部回忆或所有强化组合均已实图验证。验收结果见 [自定义强化识别验收](customization-validation-20260919.md)。

新增规则可在原有读取失败后，对原图面板追加 1.5、1.75、2 倍重读。要求两个宽度相差至少 15% 的完整读数一致、绿色文字已覆盖，而且没有其他完整读数冲突；所有尝试保留，入库再核验。绿色覆盖只允许补足规范尺寸 2 像素的 OCR 框笔画边缘；彩色消耗心形图标须匹配完整彩色模板与固定哈希才能排除。漏读的绿色效果仍会拦截。

双击 `launch-memory-library.cmd`，选中一份已导入的记忆，点击 **读取选中记忆的卡片详情**，选择点击卡片后展开浮动详情的完整窗口截图。可以多选同一份记忆的多张卡片详情。

程序读取卡名、条件与效果，匹配成功后自动填写该卡槽的自定义；双击记录可见“已自动识别自定义”。同次处理会依据当前目录为没有自定义选项的卡派生“无自定义”。原图和两次 OCR 证据会归档，可在“查看归档原图”中查看。

0.5.25 的详情规则覆盖 **びしっとキメ顔+ / 778、せのびの魔法+ / 772、アイドルになります+ / 441、私がスター+ / 171、シュプレヒコール+ / 87**。覆盖一张卡不表示所有自定义状态均已实图验证；171、87 的追加手牌强化状态仍保留未解决。各规则的 `validation` 字段记录实图与留出样本范围。

778 的原有真实图匹配为 `106x1`：好印象门槛 10、强化 200% 持续 4 回合、直接增加好印象后按 130% 计分持续 4 回合、一次限制。新增规则匹配完整详情文字，并检查绿色自定义文字是否被 OCR 覆盖，避免漏读新增效果后误判为无自定义。`私がスター+` 的抽卡是普通强化后的基础效果；不能当作自定义追加。

其他卡片没有中央绿色数字角标时，由总览自动填写无自定义；有角标则读取卡名和文本，尚无对应详情规则时保留待解决。0.5.4 起，完整记忆通过证据及目录检查后标为“已自动识别”，无需人工确认。本地模拟与排名尚未实现。PC 自动点击和滚动由独立采集器负责，见 [capture.md](capture.md)。

## 识别边界

- 通过白色独立面板定位浮动框，支持当前 PC 竖版布局及等比例放大、框在可检测区域内移动。0.5.13 起，采集器保存的弹框跨过页头时，可结合已校验的展开前截图及弹框外画面确认归属；普通手动截图仍需可读页头。不保证其他比例或框内文字被遮挡的情况。
- 日文 OCR 在本地执行。正常缩放与放大读取都必须识别正确卡名，读齐所有区分字段和不变字段，且各自唯一匹配、结果相同，才输出 token。
- 两次缩放读取不是独立准确率证明；新增真实样本及不同持有回忆的留出样本见 `tests/fixtures/recognition-v2/provenance.json`。阈值不是“准确率 95%”之类的保证；例如第 81 份的 441 详情仍可能因一行读数不足而不通过。
- 卡名末尾被 OCR 读作冒号、小假名等时，只有完整卡名对应唯一候选且末尾原图笔画确认为十字形，才修复为 `+`。独立的短 `+1` 行需额外两次数字 OCR 一致；原始置信度与复读证据均保留，不伪装成高置信读数。
- `+200%` 的正负号也必须读取正确，不能自动把误读的负号改成正号。读不齐即需要补采。
- 报告区分 `matched`、`needs-detail`、`unsupported`、`rules-changed`、`conflict`。未知与“确认无自定义”分别为 `null` 与空字符串。
- 绑定前核对记忆标题、人物、综合力、固定页头图像、数据版本和卡片 ID。同名重复卡不猜槽位，采集器须提供槽位。页头不是游戏唯一 ID，所以用户/采集会话仍要明确选中所属记忆，不能靠卡名跨记忆自动归并。
- 相同图片、槽位和规则版本的重复绑定不重复入库；不同证据出现强化冲突时保留未知。已有人工核对结果不会被自动覆盖。绑定过程检测并发修改，失败可以重试。
- 识别规则保存于 `configs/recognition/card-detail-rules.json`，绑定该卡及自定义数据的内容哈希；上游改变相关内容后会停止自动匹配，待规则更新。

## 离线运行

本地环境已准备好。日文模型在 `assets/ocr/`，其余模型在 `assets/recognition/` 或安装包内；不调用 GPT，不需要 API 密钥。测试在禁止 Python 网络连接的条件下初始化识别器并识别真实图。此测试验证识别路径不联网，不代表游戏自动采集已完成实机验收。

迁移电脑需提前安装 Python 和依赖，再离线运行；联网更新与采集将保持分离。

## 命令行

```powershell
# 独立识别详情，不修改记忆库。输出文件必须不存在。
.venv\Scripts\python.exe run.py card-detail-scan tests/fixtures/memory-library/card-detail-bishitto.png --output work/card-detail.json

# 识别并补充到明确指定的记忆。记忆 ID 可以通过 memory-list 查看。
.venv\Scripts\python.exe run.py memory-detail <memory-id> tests/fixtures/memory-library/card-detail-bishitto.png

# 同名重复卡必须显式指定槽位（1 至 6）。
.venv\Scripts\python.exe run.py memory-detail <memory-id> <screenshot.png> --slot 5
```

CLI 未匹配成功返回 2；成功匹配或重复绑定返回 0。报告例子见 `examples/card-detail-sample.report.json`。详情报告不能直接传给 URL 适配器。
