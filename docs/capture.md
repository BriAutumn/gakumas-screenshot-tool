# 独立 PC 素材采集器

本工具把游戏操作与强化识别分开。采集时不调用 GPT、不需要 API 密钥、不联网下载模型，也不需要已经支持所有卡片。只使用游戏窗口截图、鼠标点击与滚轮，不读取游戏内存。

当前为 **0.5.24 预览版**。默认预设来自用户提供的 PC 竖版界面，适用于相近比例、客户区宽度至少 400 像素的窗口。已有实际采集到卡片弹框的诊断图，完整连续流程仍需试采；不能把通过截图与模拟流程测试等同于已验证 496 份无人值守采集。

## 0.5.24：自动返回、有限重试、失败继续

本次第 246 份已经采集完成，实际停止阶段是第 80 页翻页前的选中标记定位。上一行橙色卡面也满足旧角落颜色条件，出现两个「选中框」，程序尝试重选已选中的末行回忆，游戏因重复点击直接打开详情。选中判定改为检查缩略图外侧 L 形两条臂，至少三个角同时满足；不再把卡面内部橙色当成选中框。

启动或续采时处于记忆详情，以及建立翻页标记时误开详情，都会尝试自动返回。返回操作先确认详情页及「プロデュース」「ステージ」标签；弹框先关闭，返回最多点击两次，每次重新确认页面。采集过程中返回后必须匹配原列表；启动时返回后走断点定位。已完成条目不因导航误入详情而重新采集或记为失败。

单份发生卡组不完整、详情滚动无法确认、关闭弹框后内容改变，或非 LOADING 的详情打开超时等局部问题时，保存 `diagnostic-retry` 和失败原因，返回并核对原列表，重进一次。第二次仍失败则沿用 `skipped-incomplete` 状态及 `skipped-captures.json`，保留每次尝试的原图，继续下一份。后一次成功只导出成功尝试；默认续采略过已记录待补项，勾选重试可另行补采。

鼠标/焦点异常、F8/F9、未知界面和持续加载仍保留进度暂停，不会被广泛捕获后冒充单份失败。自动返回两次仍失败时也不能在未知位置点击下一份。原日志及导航图不改写。新增橙色卡面故障图、详情恢复图，以及启动返回、误入详情恢复、首次失败后二次成功、两次失败后采集下一份、有限返回等回归。实机长时间连续采集尚未重新验证。

## 0.5.23：从当前位置断点续采与完整日志

旧会话启动后先读取当前列表画面，比较已保存页面的完整连续行；允许已有的小幅轮廓校正。多个保存页覆盖同一段列表时按全局行位置核对，优先处理其中未完成的页面；同图副本对应不同位置时不擅自选择。无完整页面时最多向上四次半格、再向下八次半格，在附近找回已保存页。刚翻页但尚未保存新页的中断，也先找回旧页再正常翻页，不凭局部尾行直接创建新编号。定位失败暂停保留进度，不自动退回全列表重放。

`session.json` 的 `checkpoint` 记录页面索引、格子索引、操作阶段和更新时间，在处理页面、进入记忆及翻页前写入；每份采集状态仍是判断是否已完成的依据，重开后不重复分配条目编号。旧会话没有 checkpoint 时也可直接通过既有页面截图特征定位，无需新建。若用户已经手动滚到较早的已保存页面，会从那个经核对的位置继续；本版不会拖动滚动条直接跳到屏幕外断点。中断在详情页时，仍需先返回独立记忆列表。

「从顶部重新核对」默认关闭。新会话首次采集、或显式勾选该选项才回到顶部。「重试待补」作用于当前位置之后；要查找更早的待补项，同时勾选从顶部核对。

每条采集进度和暂停原因追加到会话目录 `capture.log`，导航诊断另存页面索引及选中标记；历史版本未写入的进度消息不能追补，可继续查看原有 session 事件及导航原图。

本次日志显示第 135 份已完成。故障图的末行被选中框连接了轮廓，检测仅剩前一行。现沿规则网格检查边缘候选行，仅在整个行位于采集区域且至少两格具备完整上下边及侧边证据时补回；裁切和空白区域不能仅凭间距补出。故障原图验证可恢复两行并定位保存页。

回归覆盖重启后从后页继续、旧编号保留、显式从头核对、有限搜索、同图副本歧义和刚翻页即中断的恢复。实机长时间连续采集尚未完成本版验证。重启采集器，打开原会话，保持「从顶部重新核对」不勾选即可使用新续采方式。

## 0.5.4：无中央绿色数字角标，自动填写无自定义

采集和离线识别使用同一角标规则。中央区域清晰、没有绿色数字角标时，直接记录无自定义（空 token），无需逐张确认；有角标的卡由详情规则填写效果。角标过小、颜色不可用、画面缺失或同槽多图有冲突时才保留未知。离线处理重新读取原图，不依赖旧采集日志的判断，所以已有素材无需重采。

属性、道具、卡片身份和全部自定义齐全，图像证据检查及目录合法性检查通过后，记忆显示“已自动识别”，不再统一要求人工核对。选中有待解决项的记录会显示具体字段。自动状态与“已人工核对”分别记录，不伪造人工确认，不覆盖已有人工修正。自动检查是当前规则的通过状态，不是对所有卡片准确率的保证；本地模拟与队伍搜索仍未实现。

处理结束会明确显示成功入库、待解决、失败数量，并列出具体错误；有成功记录时自动打开本次结果库。采集器的“查看最近识别结果”可以再次打开本会话结果。独立“持有记忆库”窗口新增“查看最近采集结果”，可以打开所有会话中最近一次有入库记录的结果，跳过后来失败或空的处理批次。

默认手动导入库与每次离线结果库仍分别保存，以免规则更新覆盖人工核对或重复增加持有副本；实际库路径显示在记忆库窗口底部。

## 0.5.2：修复弹框遮挡页头，按角标选择详情

本次“记忆页头发生变化”已确认是卡片弹框遮住头像/姓名导致的误判。现在仅在打开前与关闭后检查页头和六卡位置：打开中的图片先存为待绑定证据，关闭后核对一致才纳入卡片详情。若真的切换记忆或未关闭弹框，仍会暂停，失败图片不会混入导入清单。

默认只展开中央下方带绿色自定义数字角标的卡片；普通“＋”、右下消耗数字不作为自定义标志。六卡总览始终保存。模糊、过小、颜色不可用或疑似角标的卡仍采详情。当前颜色规则只在已有 PC 样例验证，绿色卡面可能导致多采；从 0.5.4 起，离线识别也会用该规则自动填写无自定义。

需要保留所有原文时，可勾选“采集所有卡片详情”。选择按每次启动生效，旧会话也能使用，已完成记忆不会因此重采。每次尝试记录模式，每张卡的筛选依据保存在六卡总览的元数据中。

关闭旧采集器，用原启动入口重新打开即可生效，无需重新安装。先关闭游戏里的弹框、返回 memory 列表，再打开已有会话继续“一份试采”。本机游戏为管理员权限，请继续使用 `launch-capture-admin.cmd`。

## 0.5.1：无法切到前台 / 无法定位鼠标

本机故障检查已确认：游戏进程为高完整性（管理员权限），旧采集器为中完整性（普通权限），二者都在 Default 桌面。Windows 的输入隔离会阻止普通权限程序向更高权限程序发送鼠标输入。参见 [Microsoft SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。

1. 关闭正在运行的旧采集器。
2. 在 Windows 文件资源管理器中双击 **`launch-capture-admin.cmd`**，在 Windows 权限提示中自行确认。这个入口只提升采集器，不改变系统安全设置。
3. 选择“打开已有会话”，打开原来的 `session.json`，继续“一份试采”。不需要重新截图或重建会话。

普通权限游戏仍可使用原来的 `launch-capture.cmd`。新版开始前会只读检查双方权限，不会等到第一次移动鼠标才给出笼统错误。

自动置前现在由“开始”按钮的界面线程立即请求，等待 Windows 确认后再倒计时。若系统仍拒绝自动置前，可勾选 **“手动切换到游戏”**，点击开始后在 3 秒内点击游戏。倒计时后只检查游戏是否在前台，不会再抢其他窗口焦点。Windows 对置前权限的限制见 [SetForegroundWindow 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

鼠标定位后会读取实际位置，确认到达目标才允许点击；错误日志会保留 Windows 错误码和线程/输入桌面名称。不会解除系统的鼠标限制或切换到安全桌面。

## 第一次使用

1. 关闭 ChatGPT/Codex，正常开启 UU 和游戏。
2. 进入独立 **memory 列表**，不是竞技场编成页。保持日文界面、竖版窗口，选好本次要采的筛选和排序；列表底部应有橙色「詳細を見る」。
3. 双击项目中的 **`launch-capture.cmd`**。本机依赖已安装；迁移到另一台电脑需先联网运行 `setup.cmd`。
4. 点击“刷新游戏窗口”，选择 `gakumas` 窗口，点击“新建采集会话”。
5. 点击“一份试采”。倒计时后程序会把游戏置于前台、回到列表顶部、跳过明确识别为制作专用的条目，采第一份可用记忆。操作期间让鼠标留给采集器。
6. 试采结束后，查看日志和会话文件夹中的图片，确认属性、道具、六张卡及选中卡槽的详情都在正确的文件中；“完整”只表示当前模式要求的画面采到，不表示强化已经识别正确。
7. 再选择本批数量（默认 20），点击“开始 / 续采”。数量是本次新增或重试的记忆数；跳过制作专用条目不计入。可分批续采，也可将数量设置得足够大采到列表底部。

采集器先读每个缩略图上的制作专用文字；确认制作专用就保存证据并直接跳过，不点击该条目（这种条目无法选中，点击不会移动选中框）。普通记忆逐份：列表选中 → 截列表定位图 → 打开详情 → 切换 Stage → 回到详情顶部截图 → 向下滚动找到完整六卡 → 筛选角标，逐张采集选中卡的详情并关闭核对 → 返回并核对列表 → 下一份。翻页只在找到前后页重叠行时继续；当前检测完整的三列缩略图行，不按内容哈希删除相似或相同的持有副本。

## 暂停与续采

0.5.15 起，打开详情或切换 Stage 时最多等待 30 秒；不会把仍显示 LOADING 的静止列表当成点击失败，也不会在加载中重复点击。超时保留进度，待游戏加载结束、返回列表后继续原会话。F8/F9 在等待中仍生效。

续采时若旧坐标不匹配，会重新寻找旧页完整的连续行序列；只有各格内容和顺序一致且对应唯一时才采用当前位置。新出现的相邻行留给后续翻页处理，不插进旧页的格子编号。仅滚动落点不同可以恢复；不能唯一对应、内容或顺序变化仍会暂停，不放宽缩略图内容阈值。

同一页选择记忆、从详情返回及恢复进度时，会在已保存的格子位置重新提取实际画面并逐格比对，不依赖重新识别选中框附近的边框。翻页仍需完整缩略图行及重叠行校验。

列表顶部固定区域可能把缩略图裁去一小条；这种不完整比例的轮廓不参与翻页匹配，避免将局部画面当成整张记忆。自定义角标核对卡片下方中央绿色圆形及白色字形，不再因区域内有少量绿色就补采。分辨率不足、失色或圆形/字形确实不确定时仍会采详情；关闭“采集所有卡片详情”即可使用此选择规则。

详情页滚动采用四次短间隔滚轮事件后统一等待画面稳定，确认滚动条到顶/到底后省去重复滚动；没有读清滚动条时保留画面不再变化的后备检查。`session.json` 中每份的 `attempts[].detail_scrolls` 记录每轮事件数、方向及包含截图稳定等待的秒数，便于实机比较速度。

- **F8 暂停，F9 停止**；均保留原图和进度。切换到其他窗口、游戏最小化、窗口移动/缩放或检测到遮挡也会暂停。
- 点击工具窗口本身会使游戏失去焦点，因此也会暂停。程序不会为了继续采集而反复抢焦点。
- 继续前，手动关闭尚未关闭的卡片详情，回到独立 memory 列表。可以停在任意列表滚动位置，程序会回顶部并核对已经过的页面后继续。
- 关闭重开工具后，点击“打开已有会话”，选该目录的 `session.json`。
- 一份记忆采到一半被打断，续采时重采这一份，保留旧尝试的原图，清单只引用最新完成尝试，避免混合不同卡槽。
- 某张卡的弹框经过重试仍未确认，但能返回总览，则保存诊断图、标记需补采，再继续后面的卡和记忆。可勾选“续采时重试缺少详情的记忆”。
- 新增/删除/合成记忆、切换筛选、改变排序后，旧位置不一定有效。程序发现不一致会暂停；恢复原列表，或另建会话。不能自动证明两个会话中的相同画面是同一份持有副本。
- 单机同一时间只允许运行一个鼠标采集任务。进度清单原子写入，每个原图带 SHA-256 校验，强制关闭后不会把半写入的清单当作成功进度。

## 如果默认位置不合适

在游戏显示对应页面时点击 **“标定当前画面”**，程序抓取游戏客户区，打开静态截图供你点位置；标定窗口上的点击不会传入游戏。

- 在列表画面：标记完整缩略图区域、右侧滚动条轨道、橙色详情按钮中心、列表内的滚轮位置。
- 在详情画面：标记 Stage 标签、下方详情滚轮位置、双箭头返回按钮、能够关闭弹框的空白区域。关闭点应远离卡片、保存、合成、转换和其他按钮。
- 状态判断不准时，可调整 Stage 标签区域、列表橙色按钮区域、详情固定页头和滚动内容区域。
- 点位项目点一次；区域项目点左上、右下。保存后**新建会话**使用新标定；既有会话保持原标定，避免恢复时混用坐标。
- 颜色、卡片四加二布局与三列列表检测仍针对现有样例，并非任意界面通用识别。特殊布局、黑屏截图、过长/遮挡的详情或其他语言可能需要后续修改检测器。暂停时尽可能保存当前游戏诊断图，不会改为截取其他桌面窗口。

列表到顶/到底还需滚动条位置证据；列表短到不出现滚动条、滚动点不生效等情况会暂停，不会仅凭画面不动宣称采完。

## 关掉游戏后处理

1. 重新打开采集器，加载会话；此时不需要游戏，也可以打开 GPT。
2. 点击 **“离线识别本会话”**，读取所有已完成/需补采记忆的原图，合并属性与卡组，再按保存的卡槽读取详情。
3. 点击“查看最近识别结果”。支持的强化自动填写，不支持的规则保留原文、原图和未解决状态。
4. 后续修改识别规则，再点“离线识别本会话”即可重跑，原图和以前的结果不被改写。每次运行有独立结果库，不会在同一份持有库里累加重复副本。

处理状态表示程序是否完成该轮处理；记忆状态另外区分“已自动识别”“有待解决项”“已人工核对”。目前详情强化规则仍仅支持「びしっとキメ顔+」；其他卡没有中央角标时可自动确定无自定义，有角标而规则尚不支持时仍需补规则。模拟和队伍优化未实现。

## 文件位置

```text
data/captures/<时间-会话编号>/
  session.json                采集身份、配置、列表页、每份进度和问题
  batch.json                  可重复生成的最新完成尝试清单
  raw/navigation/             列表页与导航诊断图
  raw/<持有副本编号>/           原图；role 和 slot 对应关系在 session.json
  processing/<处理时间编号>/
    results.json              本轮各记忆与卡槽的识别结果、未解决问题
    *-memory.json             总览识别报告
    *-card-*.json             卡片详情文字和强化报告
    memory-library/           本轮独立结果库与归档证据
```

备份时保留整个会话目录。原图多于识别结果是正常的：每个被选中展开的卡槽都有点击前后证据，失败和续采尝试也不覆盖旧图。`pending-tooltip` 是尚未通过关闭后身份核对的原图，不参与离线导入；文件名保留初始名称，最终角色以 `session.json` 为准。

命令行离线重处理：

```powershell
.venv\Scripts\python.exe run.py capture-process "data/captures/<会话目录>"
```

## 已验证的范围

真实提供的图片用于列表三列九格、制作专用文字、详情六卡、浮动详情面板检测；本地 OCR 初始化与处理测试禁止网络连接。模拟游戏流程覆盖六卡逐个展开/关闭、跨页重叠、同内容不同副本、不完整弹框、中途暂停恢复、列表变化、返回失败与焦点检查。真实游戏的滚动幅度、点击响应、弹框关闭方式和多份连续采集仍需首次试采验证。
